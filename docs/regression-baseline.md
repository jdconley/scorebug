# Scoring and worker recovery regression baseline

Recorded during the September 13 assessment against the original prototype.
These are acceptance requirements for server and native-client implementation,
not passing automated tests. The legacy browser scorer will not be extended.

| Case                      | Observed behavior / evidence                                                                                                                                                                                        | Required regression gate                                                                                                                                                                                       |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Relaunch recovery         | Refreshing the prototype after creating a game loses the usable active UI; creating another returns `409 game_in_flight`. The server has lookup by known ID but no active-game discovery.                           | Milestone 1: terminate/relaunch a native scorer and recover the same match, current revision, and scoring role. A second native phone discovers and joins it.                                                  |
| Server restart            | `GameStore` is in memory, so a server process restart discards matches and scores.                                                                                                                                  | Milestone 1: real SQLite restart test preserves identity, score, role, command receipts, and desired broadcast state.                                                                                          |
| Late worker               | Creating a game while no worker is connected logs `home_not_connected_on_start`. Connecting the worker later sends no current game; `HomeBus.attach` only stores the socket. Reproduced with a real WebSocket.      | Milestones 1–2: a late or restarted worker receives an authoritative snapshot, starts only the current generation, and renders the current score once the source is ready.                                     |
| Failed end request        | Code inspection: the legacy `App.tsx` clears active state in a `finally` block even when `api.endGame` fails. Fault injection was not run during the assessment.                                                    | Milestone 1: inject failed delivery and lost acknowledgment separately. Native UI keeps the match and shows pending/error state, retries the same command ID, and reconciles before declaring the match ended. |
| Tied set                  | At a tied score, the prototype's End Set increments the away set count. Reproduced interactively; `Scoreboard.tsx` picks away whenever home is not strictly ahead. The server accepts unrestricted score snapshots. | Milestone 1: server rejects tied-set completion; both native clients show the rejection and preserve score. Apply configured win-by-two/deciding-set rules on the server.                                      |
| Concurrent/offline points | No command IDs, revisions, or scorer authority exist; clients send replacement snapshots. This is a design gap, not a completed fault-injection test.                                                               | Milestone 1: duplicate requests and lost replies apply once; stale revisions and commands from a previous scorer/set cannot silently replace current state.                                                    |

The native harness currently tests address validation and camera-free launch only.
Convert these requirements into protocol fixtures, real API/SQLite tests, Swift
tests, and multi-device native UI tests as the corresponding behavior lands.
Do not count skipped or expected-failure placeholders as coverage.
