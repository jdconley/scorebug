# Fixed240 qualification at 3 Mbps

The 240p fixture now preserves media at a 4 Mbps uplink limit and measures about
1.99 Mbps video payload / 2.25 Mbps average wire load. The next experiment lowers
only the scheduled uplink ceiling to 3 Mbps. The same archive, workload, encoder,
worker, 180-second hold and 60/60/60-second phases remain in place.

Add explicit `rate3m` fixture admission for fixed240 only. Keep adaptive fixtures
and probes on their existing qualified configurations. The schedule qualifier
accepts an expected profile supplied by the caller (default `rate4m` preserves
existing callers), then validates the requested/applied rate and corresponding
wire-byte ceiling against that profile. Do not infer the expected profile from
untrusted evidence, or allow a 4 Mbps run to qualify as 3 Mbps.

capacity, automatic recovery, profile-transition continuity, physical-device radio
behavior or the requested nominal encoder bitrate. The full progressive streaming
and native Watch goals remain open.

## Verified outcome

All 1,202 tooling tests pass, including the seven schedule tests. Three retained
4 Mbps runs (`native-app-3Zrmzl`, `native-app-H73kCA`, `native-app-hB2BBX`) replay
with exactly unchanged qualification results and are rejected as 3 Mbps evidence.
No Apple runtime code changes in this slice; the actual native run rebuilds and
exercises the app against the new fixture schedule.

`native-app-2H0AUs` passes the actual 180-second fixed240 scenario. It preserves
6,386 consecutive archive frames and 5,981 consecutive retained live frames
(192 through 6,172), all 106 archive/99 live audio markers, and clean full decodes.
The minimum reported receiver cadence is 30 fps. The applied 3 Mbps phase lasts
60,000.510291 ms and forwards 16,868,736 wire bytes (about 2.25 Mbps average).
There are no proxy drops and all process owners join. Native format evidence
confirms 426×240 before the proxy. Eight retained video-cost windows peak at
1,989,143.29 bps; the requested 350 kbps remains unachieved.

Independent verification confirms actual schedule configuration, native media,
archive completion and accounting. The unchanged control passes and 16 damaged
variants are rejected, including wrong configured/result/requested/applied/queue
rates. Runtime sources and evidence are frozen in
`artifacts/qa/rate3m-final-verification.json`.

establish cellular, jitter/loss tolerance, a capacity estimate, or physical-device
