# Separate native scorer during physical capture

**Goal:** Verify a second native iPhone app can take over scoring while the physical filming phone keeps recording and publishing through the real overlay proxy and both MP4 outputs.

**Architecture:** Reuse the physical phone vertical and its guarded archive/export teardown. Add an explicitly selected separate-scorer mode and a native scorer UI method on one owned iOS26.2 simulator. The scorer uses the full Scorebug app, normal setup and buttons; no camera source injection, browser, direct scoring requests or changes to production policy. The lab remains unimpeded for this smoke; adaptive collapse and paired Watch qualification stay separate.

**Status:** Design ready; implementation and verification pending. Physical phone runner LAN privacy does not gate this route: only the Scorebug app connects to the API. The simulator scorer does not use a recovery controller.

## Interaction and evidence contract

1. Build both phone and simulator products before recording. Create one uniquely named simulator using an already installed runtime; delete only that owned simulator after both test commands join. Record source/binary/private-xctestrun hashes before/after.
2. Start a fresh lab and match. Start the simulator scorer test first. It configures the full app using the normal native Score fields, joins without takeover and waits for the filming phone's acknowledged HOME1/AWAY0 plus producing-output status. Its camera permission remains ungranted; it immediately selects Score and never starts capture (the normal app initially displays Film).
3. The filming phone performs the existing guarded setup, starts clean camera recording and SRT, confirms producing output and awards its normal HOME point. In the explicit new mode it waits for the external AWAY point instead of ending the usual12-second live hold.
4. The other native app takes over through the native button, awards AWAY exactly once, observes1–1, holds12seconds, undoes exactly once, observes1–0, awards AWAY once more and observes1–1. It holds the final score30seconds so the phone and decoded output can observe it. No automatic retaps, direct command injection or remote match end.
5. Camera side observes1–1,1–0,1–1 in order while checking local recording duration and publishing/worker states between observations. Each first/final score is held long enough for polling; scorer uses12-second intermediate holds. The camera itself holds final1–1 for30seconds, checking advancing archive duration and publishing/worker health, independently of the scorer’s hold. It then stops only streaming, proves at least three seconds of continued archive, stops recording, exports the actual new recording and retains its ID. Preserve a scoring failure through orderly stop/export.
6. Validate the two exact non-skipped XCTest leaves and their role-specific evidence. Query the fresh lab's durable command log: camera takeover→HOME→other scorer takeover→AWAY→undo→AWAY, ordered by accepted outcome revisions and scorer epochs, distinct score actors and exactly one application of each command identity. Transport retries of the same ID are allowed, extra accepted/rejected commands fail this fixed scenario. Confirm one continuous capture/source association; camera-free scorer has no recording association. Do not equate the filming phone’s scoring actor with its independently generated capture actor. Bind role-specific native observations and command semantics to the two distinct scorer identities; bind the sole recording/broadcast separately.
7. Collect only the actual new phone recording/export, mock destination MP4 and proxy MP4. Fully decode all three; check stream formats, output cadence/PTS/audio gaps, scorebug changes1–0→1–1→1–0→1–1 and clean archive/continued tail with camera-appropriate checks. Regular PTS without fixture identities does not establish fresh camera content or frame-exact correspondence. A workflow pass is not full media qualification, and this single simulator scorer does not prove a second physical phone or Watch.

## Alternatives considered

A server-only second scorer cannot prove native UI behavior. A second full filming simulator would consume more resources and fail to exercise real camera behavior. The mixed physical-camera/native-simulator-scorer route directly tests the requested role separation with the available devices, without claiming absent Watch/hardware coverage.
